# AI/LLM Service Code Style Rules

LLM を利用するサービス（チャット・分析等）の実装規約。フレームワークを問わず適用できる原則を記載する。

---

# 構成

- プロンプトはコードから分離し、専用ディレクトリ・モジュールに切り出す（インラインの長大な文字列リテラルを埋め込まない）
- 設定値（モデル名・APIキー・プロバイダー等）は環境変数経由で注入し、コードにハードコードしない
- サービス層でオーケストレーション（プロンプト組み立て・LLM呼び出し・後処理）を行い、ルーティング層に業務ロジックを書かない

---

# 判断理由のコメント必須化

再現性・保守性確保のため、推論結果に影響するパラメータには理由をコメントで残す。記載項目・記載例の詳細は [comments.md](comments.md) を参照。

---

# プロバイダー切り替え

- LLM プロバイダー（OpenAI / Anthropic 等）は設定で切り替え可能な設計にし、プロバイダー固有のコードをサービス層に直接埋め込まない
- プロバイダー抽象化層（ファクトリ関数等）を1箇所に用意する

---

# エラー処理・フォールバック

- 外部LLM呼び出し・DB接続の失敗時に、ユーザー体験を損なわないフォールバック挙動を用意する（例: データなしプロンプトへの切り替え）
- フォールバックが発生した場合はログに記録し、サイレントに握りつぶさない

---

# コスト・パフォーマンス配慮

- 会話履歴やコンテキストサイズに上限を設け、無制限に増加させない
- 長時間かかる推論は同期エンドポイントで待たせず、非同期処理（バックグラウンドタスク等）で受け付ける設計を検討する
