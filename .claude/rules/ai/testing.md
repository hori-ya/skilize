# AI/LLM Service Testing Rules

LLM を利用するサービスの自動テストに関する規約。

---

# 基本方針

- 実際のLLM APIやDBを呼び出すテストは書かない（コスト・非決定性・実行速度の問題があるため）
- LLM呼び出し・DBアクセスは全てモック化し、サービス層のロジック（プロンプト組み立て・分岐・後処理）を検証する

---

# 検証観点

- 入力条件（モード・パラメータ）に応じて正しいプロンプト・設定が選択されるか
- LLM呼び出し失敗時・DB接続失敗時に想定したフォールバックが発火するか
- 出力の後処理（フォーマット変換等）が正しく行われるか

---

# 避けるべきこと

- LLMの生成内容そのものの妥当性をテストで断定的に検証すること（非決定的なため、構造・分岐の検証に留める）
- 本番相当のAPIキーを使ったテスト実行
