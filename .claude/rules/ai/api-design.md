# AI/LLM Service API Design Rules

LLM を利用する内部サービスのAPI設計規約。

---

# 内部認証

- 他サービスからのみ呼び出される内部APIには、内部専用の認証キー（共有シークレットヘッダー等）を必須にする
- 公開エンドポイントの認証方式（JWT等）とは区別する

---

# リクエスト・レスポンス設計

- リクエストボディはスキーマ定義・バリデーションライブラリで検証する（型不一致・必須項目欠如を早期に拒否する）
- レスポンスは呼び出し元が扱いやすい構造化データ（JSON）で返す
- LLMの生出力をそのまま返さず、必要な後処理（フォーマット統一等）を行ってから返す

---

# 非同期処理パターン

- 処理時間が長い推論（分析等）は、リクエスト受付時に即座に受理レスポンス（202等）を返し、バックグラウンドタスクで処理する
- 処理結果はステータスを永続化し、別エンドポイントやポーリング/通知で取得できるようにする
- 同期応答が必要な用途（チャット等）は、タイムアウト・リトライ方針を明示する

---

# レート制御・保護

- 外部LLM APIのレート制限・コストを踏まえ、呼び出し元（バックエンド等）からのリクエスト頻度を制御する
- 異常に大きい入力（長大なプロンプト等）は事前にサイズ制限で拒否する
