# Error Handling Rules

例外・エラー処理に関する規約。バックエンド・フロントエンド共通の原則を記載する。

---

# 基本方針

- 例外は「呼び出し元が対処できる情報」を持たせて送出する
- 例外を握りつぶさない（catch して何もしないことを禁止する）
- 内部実装の詳細（スタックトレース・SQL文等）をクライアントに直接返さない

---

# エラーコード設計

- エラーはメッセージ文字列ではなく、一意なエラーコード（`SCREAMING_SNAKE_CASE`）で識別する
- エラーコード → 表示メッセージの変換は、呼び出し側（フロントエンド等）の翻訳・表示層に任せる
- サーバー側のエラーオブジェクトに、表示用の自然言語文字列を直接埋め込まない

---

# 例外の分類

| 分類 | 例 | HTTPステータスの目安 |
|---|---|---|
| クライアント起因（入力不正） | バリデーションエラー | 400 |
| 認証エラー | 未認証・トークン期限切れ | 401 |
| 認可エラー | 権限不足 | 403 |
| リソース不在 | 対象データが存在しない | 404 |
| 競合 | 楽観ロック競合・重複登録 | 409 |
| サーバー起因 | 想定外の例外・外部サービス障害 | 500 |

---

# グローバルなエラーハンドリング

- 個々の Controller/Router で例外処理を重複実装せず、共通のエラーハンドラーに集約する
- 未捕捉の例外も共通ハンドラーで捕捉し、統一フォーマットのエラーレスポンスに変換する

---

# フロントエンド側の扱い

- APIエラーコードの解釈・表示メッセージへの変換は共通ユーティリティに集約する
- 未定義のエラーコードを受け取った場合のデフォルト表示（汎用エラーメッセージ）を用意する
