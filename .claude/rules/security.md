# Security Rules

アプリケーション全体（バックエンド・フロントエンド共通）に適用するセキュリティ規約。特定の言語・フレームワークに依存しない原則を記載する。

---

# 認証情報の扱い

- パスワードは必ずハッシュ化（bcrypt / argon2 等の適応型ハッシュ関数）して保存する。平文保存・可逆暗号化は禁止する
- 認証トークン（JWT・セッショントークン等）の保存場所はプロジェクトごとに1箇所に統一する（例: メモリ、`localStorage`、httpOnly Cookie）。複数の保存場所を混在させない
- トークンの有効期限を設定し、無期限のトークンを発行しない

---

# シークレット管理

- APIキー・DB接続情報・署名鍵等の機密情報を設定ファイルにハードコードしない
- 機密情報は環境変数、またはシークレット管理サービス経由で注入する
- `.env` 等の機密情報ファイルはバージョン管理対象から除外する（`.gitignore`）。雛形（`.env.example`）のみをコミットする

---

# ログ出力

- パスワード・パスワードハッシュ・認証トークン・氏名/メールアドレス等の個人情報をログに出力しない
- 出力が必要な場合はマスキングするか、代替の識別子（ユーザーID等）を用いる
- 詳細は [logging.md](logging.md) を参照

---

# 認可・アクセス制御

- ロール・権限による制御はエンドポイントの入り口（Controller/Router/ミドルウェア）で宣言的に行う。UI 側の表示制御のみに頼らない
- 「対象が見つからない」と「権限がない」を区別してレスポンスを返す場合は、情報漏洩（存在有無の推測）につながらないか検討する
- ユーザー列挙攻撃対策として、ログイン時は「ユーザー不在」と「パスワード不一致」を同一のエラーにする

---

# CORS

- 許可オリジンは環境変数等の設定値で明示的に管理する
- 本番環境でワイルドカード（`*`）による全許可を行わない

---

# 入力検証・インジェクション対策

- 外部からの入力はシステム境界（Request/Controller 層）で必ずバリデーションする
- DB アクセスはパラメータ化クエリ・ORM を使用し、ユーザー入力を直接クエリ文字列へ連結しない
- ファイルアップロードはサイズ・拡張子・MIMEタイプを検証する

---

# 依存関係・構成

- 依存ライブラリの既知の脆弱性を定期的に確認し、セキュリティパッチを適用する
- 本番環境向けの設定（デバッグモード無効化、詳細エラー非表示等）を開発環境と明確に分離する

---

# ブルートフォース対策

- ログイン等の認証系エンドポイントには、試行回数制限やロックアウト等の対策を検討する
