# Logging Rules

アプリケーションログの記載・出力に関する規約。

---

# ログ基盤

- 構造化ロギングフレームワークを使用し、標準出力への直接書き込み（`print` 等）に頼らない
- リクエスト単位のトレースID（相関ID）をログに含め、障害調査時に一連の処理を追跡できるようにする
- フォーマットは開発・本番で共通にし、ログ集約基盤で解析しやすくする

---

# ログレベルの使い分け

| レベル | 用途 |
|---|---|
| ERROR | 5xx相当のエラー・外部サービス障害・想定外の例外 |
| WARN | 認証失敗・権限エラー・バリデーションエラー等、4xx相当の異常 |
| INFO | 業務上意味のある操作（作成・更新・削除・状態遷移・重要なイベント） |
| DEBUG | 開発時の詳細調査用。本番環境では出力しない |

---

# 出力すべき操作

- 状態を変更する操作（作成・更新・削除・有効化/無効化等）
- 重要な業務イベント（申請・承認・完了等の状態遷移）
- 非同期処理の開始・完了・失敗

---

# ログ出力禁止事項

以下はログに出力しない。

- パスワード・パスワードハッシュ
- 認証トークン（JWT・APIキー等の値そのもの）
- 氏名・メールアドレス等の個人情報
- クレジットカード番号等の機密情報

該当箇所を出力する必要がある場合は、マスキングまたは代替の識別子（ユーザーID等）を使用する。詳細は [security.md](security.md) を参照。

---

# 例外処理とログ

- 例外を握りつぶす（何もログを出さずに無視する）ことを禁止する
- キャッチした例外は原因が追跡できる情報と共にログへ記録する
