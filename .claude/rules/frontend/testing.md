# Frontend Testing Rules

フロントエンドの自動テストに関する規約。

---

# ファイル配置

- テストファイルはテスト対象コンポーネント/モジュールと同じディレクトリに配置する（colocation）
- 命名は `対象ファイル名.test.tsx`（または `.test.ts`）とする
- テスト専用フォルダへの集約は行わない（機能単位でまとまりを保つため）

---

# テスト対象・観点

- ユーザーから見える振る舞い（表示内容・操作結果）を検証する。内部実装の詳細（state名・関数名）に依存したテストは書かない
- API 呼び出しはモック化し、コンポーネントのロジックのみを検証する
- スナップショットテストのみに依存しない（意図が読み取れる assertion を書く）

---

# 優先順位

1. ユーザー操作 → 期待される表示・API呼び出しの検証
2. 条件分岐（ロール・状態による表示切り替え等）
3. 異常系（API エラー時の表示）

---

# モック化の方針

- HTTP 通信は必ずモック化し、実バックエンドに依存しないテストにする
- 日付・乱数など非決定的な要素はモック化する
